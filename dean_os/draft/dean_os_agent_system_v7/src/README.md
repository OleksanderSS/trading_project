# 🏛️ Архітектура проєкту DEAN

DEAN побудований на принципах чистої, багатошарової архітектури, де кожен шар відповідає за конкретну задачу, а потік даних рухається послідовно від збору сирих даних до фінального торгового рішення.

## 🌊 Послідовний Потік Даних (Sequential Data Flow)

Система організована як "водоспад" з п'яти послідовних стадій, що забезпечує прозорість, масштабованість та легкість у тестуванні.

---

### 📦 **Stage 1: Акумуляція даних (Data Accumulation)**
*   **Компонент**: `src/data`
*   **Відповідальність**: Збір, очищення та зберігання всіх необхідних даних (ціни, новини, он-чейн метрики). Формування єдиного "фундаменту" для всієї системи.
*   **Результат**: Чисті, готові до використання часові ряди та датасети.

### 🧠 **Stage 2: Контекст ринку (Market Context)**
*   **Компонент**: `src/market_context`
*   **Відповідальність**: Аналіз даних для визначення поточного стану ринку (режим, волатильність, сентимент). Створення "відбитку пальців" (fingerprint) для кожної точки даних.
*   **Результат**: Кожна точка даних збагачена метаданими про ринковий контекст.

### 🧩 **Stage 3: Генерація сигналів (Signal Generation)**
*   **Компонент**: `src/predictions`
*   **Відповідальність**: Обробка даних за допомогою набору різнорідних моделей (LSTM, Transformer, XGBoost тощо) для генерації прогнозів.
*   **Результат**: Набір незалежних прогнозів від кожної моделі.

### ⚖️ **Stage 4: Ансамблювання (Ensembling)**
*   **Компонент**: `src/ensembling`
*   **Відповідальність**: Надання інструментів для інтелектуального комбінування прогнозів. **Цей шар тепер містить навчену мета-модель (`StackedEnsemble`), яка знає оптимальні ваги для об'єднання сигналів базових моделей.**
*   **Результат**: Єдиний, зважений прогноз, що враховує силу та слабкість кожної моделі.

### 🤖 **Stage 5: Прийняття Рішень (Decision Making)**
*   **Компонент**: `src/trading`
*   **Відповідальність**: Фінальний етап, де зважений прогноз проходить через низку фільтрів для прийняття остаточного рішення (BUY/SELL/HOLD).
*   **Нова архітектура**: Компонент **`ConsensusEngine`** тепер завантажує **навчену мета-модель з Stage 4** для отримання базового прогнозу. Потім він застосовує до цього прогнозу свої унікальні фільтри, такі як:
    *   **KNN-фільтр**: Перевірка на історичні аналоги.
    *   **"Критик"**: Фінальне вето на основі аналізу минулих помилок.
*   **Результат**: Фінальне торгове рішення, готове до виконання.

---

## 🎯 Ключові принципи

*   **Розділення відповідальності**: Кожен компонент робить одну річ і робить її добре.
*   **Тестованість**: Кожну стадію можна тестувати незалежно.
*   **Масштабованість**: Легко додавати нові джерела даних, моделі або фільтри, не руйнуючи існуючу логіку.

# Operator Console Workflow

## Dashboard sections

1. Daily run status
2. Source/data health
3. New major events
4. Open hypothesis tokens
5. Evidence gaps
6. Analyst-pipeline disagreements
7. Blocked gates
8. Incidents
9. Learning candidates
10. Paper/shadow/supervised status, when enabled

## Operator actions

- approve report item;
- correct field;
- reject unsupported claim;
- request more evidence;
- mark source weak;
- lower/raise confidence;
- create incident;
- create eval case;
- approve learning candidate;
- reject pattern update;
- escalate to manual investigation.

## Design rule

The operator console is not a trading terminal in early stages.

It is a review, learning, audit, and governance console.

# Handoff Package Role Matrix

| # | Package | Role | Codex action |
|---|---|---|---|
| 1 | Full context bundle after 385 | Main staged architecture inventory | Read first for lifecycle, branch boundaries, analyst/pipeline/orchestrator design. |
| 2 | Codex integration kit after 385 | Harvest/adapt instructions | Use as integration policy; prevents blind merge. |
| 3 | Domain learning template kit v3 | Domain agent knowledge, source registry, RAG, causal patterns | Map to collectors, event packets, source routing, domain analysts. |
| 4 | Eval / Observability / Audit Kit | Quality gates, grounding, leakage, metrics, alerts | Map to pipeline guards, eval stage, monitoring, daily audit. |
| 5 | Macro Regime / Historical Hypothesis Kit v3 | Macro regimes, historical analogs, expectation gap, event graph learning | Map to context analyzers, causal methods, hypothesis ledger. |
| 6 | Automation / Execution Governance Kit v2 | Daily automation, maturity ladder, pipeline controller daily governor | Map to scheduler/orchestrator/pipeline controller, not directly to trading. |
| 7 | Advanced Governance Template Kits | Provenance, debate, postmortem, portfolio governance, event graph closure | Use to add reproducibility, learning closure, incident handling, capital governance. |
| 8 | Operator Review / Synchronous Learning Kit | Human-agent parallel review, reports, feedback labels | Map to review console/workflow and learning examples. |
| 9 | Agent Memory / Knowledge Governance Kit | What agents may remember/promote/deprecate | Map to memory/pattern/profile governance. |
| 10 | Strategy Library / Playbook Governance Kit | Strategy registry, input contracts, regime compatibility, promotion gates | Map to strategy/playbook layer before replay/paper. |
| 11 | Scenario Stress Testing Kit | System-level stress scenarios | Map to stress tests across agents, pipeline, risk, execution, audit. |

## Rule

The packages are complementary. They should not be integrated as 11 separate architectures. They should be reduced into one coherent repo design.

# Patterns Module (`src/patterns`)

The `patterns` module is a specialized intelligence layer dedicated to identifying, analyzing, and integrating structural market patterns into the trading pipeline. It serves as an expert system that bridges technical analysis with machine learning, operating primarily in **Stage 3 (Feature Engineering)** and **Stage 6 (Signal Filtering)**.

## Core Components

1. **`pattern_analyzer.py`** — ARCHIVED to `src/archive/patterns/`, and
   disabled in `analysis.yaml`. It was the intended detection engine. It identifies technical patterns including:
    - **Candlestick Formations**: Engulfing, Hammers, Dojis, etc.
    - **Chart Formations**: Geometric structures like Head & Shoulders, Double Tops/Bottoms, and Triangles.
    - **Key Levels**: Support, resistance, and supply/demand zones.
2. **`pattern_recognition_adjustment.py`**: An integration layer that adjusts model predictions. It modifies the primary ML model outputs or confidence levels when significant patterns are detected, acting as a "sanity check" or a multiplier for trade signals.
3. **`pattern_tuning.py`** — DOES NOT EXIST in this tree. A utility for optimizing detection parameters (thresholds, sensitivity, and lookback windows) for individual tickers to ensure maximum historical relevance.

## Pipeline Integration

- **Stage 3 (Features)**: Patterns are extracted and added as input features for models, providing qualitative structural context to quantitative data.
- **Stage 4 (Modeling)**: Models learn to weight these patterns alongside technical and sentiment indicators.
- **Stage 6 (Signals)**: Patterns act as logic-based filters to confirm or veto final trade signals generated by the consensus engine.

## Standards and Validation

To maintain consistency across the system, all performance and success-rate calculations within this module are delegated to the central **`src/metrics/calculator.py`**. This ensures that the evaluation of a pattern's effectiveness remains unified with the rest of the analytical pipeline.
